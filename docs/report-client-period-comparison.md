# Client period comparison in the console

Source 13 (`NativeSaleClientPeriodComparison`) adds the server-advertised preset **Клієнти: порівняння періодів**. The operator chooses both date windows explicitly. Saved templates preserve current dates, version 1 comparison dates, exact ClientAgreement IDs, selected measurements, groupings, ordering, filter expressions and template revision. Unsupported or malformed configurations fail before report or template requests. Source 12 retains its existing single-period contract.

Rows support the six published client/agreement/product dimensions. Columns contain any nonempty distinct subset of current count (25), comparison count (26), signed difference (27), and percentage difference (28). A comparison window cannot be inferred, shifted automatically or applied to another dataset.

The workbook reader validates both event periods, the UTC read interval, all eight provenance notes and selected resource captions. Counts are integers; differences preserve their sign; percentage cells contain percentage values (2.34 means 2.34%), displayed and exported to two decimal places without multiplying by 100. Server publication rounds halfway values away from zero. Independently unknown periods remain blank, and both counts must be known for either derived measure. A confirmed previous count of zero gives 100%, including confirmed 0/0.

All four measures are nonadditive in the browser. The console preserves server totals computed from per-period client identity unions. Local filtering removes stale totals, and charts use only leaf values, retaining unknown gaps and negative differences. A server-confirmed empty report keeps its explicit state and only the selected grand values from 0/0/0/100; no client row is invented. The display wraps eight logical notes without changing the physical XLSX/CSV metadata rows.

Validation includes builder and template boundaries, strict imports, actual XLSX file input, table/CSV and all three chart kinds. Seven immutable synthetic XLSX files generated by the actual backend writer were also read with the production `read-excel-file` package and checked against independent union/count controls, including known, independently unknown, empty, selected-subset and ordered cases. Actual PascalCase capabilities were consumed. Evidence is recorded in the private wave 18 console directory.

This feature describes current exact native client ownership for posted sale facts in two event periods. It does not certify the historical 1C register, source permissions, automatic saved 1C variant translation or full numeric parity with 1C.
