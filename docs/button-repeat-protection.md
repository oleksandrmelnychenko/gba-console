# Захист від повторних дій

Кнопки асинхронних операцій мають блокувати повторний запуск до першого `await`,
а не покладатися лише на React-стан `loading`. Це стосується також `onSubmit`:
відключення кнопки саме по собі не є перевіркою всередині обробника.

## Форма з прапорцем зайнятості

`src/shared/hooks/useBusyState.ts` повертає стан для інтерфейсу, setter і
синхронний `tryStart`. Виклик `tryStart` одночасно захоплює блокування та вмикає
індикатор. Всі дії зі спільним станом зайнятості використовують те саме блокування.

```tsx
const [saving, setSaving, tryStartSaving] = useBusyState()

async function submit(event: FormEvent<HTMLFormElement>) {
  event.preventDefault()
  if (!isValid() || !tryStartSaving()) return
  try {
    await save()
    await refresh()
  } finally {
    setSaving(false)
  }
}
```

Існуючий `loading={saving}` або `disabled={saving}` залишається на кнопці.
Не скидайте стан зайнятості, поки ще виконується операція. У `useCallback`
додайте `tryStartSaving` до залежностей.

## Стан у reducer або батьківському компоненті

`src/shared/hooks/useSingleFlight.ts` захищає весь обробник, включно з його
наступними запитами, оновленням інтерфейсу та повідомленнями. Повторний виклик
із тим самим ключем отримує поточний Promise. Для кожного ключа має бути один
тип результату та одна логічна дія. Різні ключі й різні екземпляри компонента
незалежні.

```tsx
const runActionOnce = useSingleFlight()

async function submit(event: FormEvent<HTMLFormElement>) {
  event.preventDefault()
  return runActionOnce('submit', async () => {
    // Існуюча валідація, reducer, API-виклики та обробка помилок.
  })
}
```

`preventDefault` виконується для кожної події, включно з повторною. Блокування
знімається після успіху або помилки без таймера чи автоматичного повтору запиту.
Скасування застарілих пошукових запитів і переходів між даними зберігає свою
окрему семантику; їх не треба механічно перетворювати на одноразові дії.

## Перевірка

- Unit-тести обох hooks: повторний виклик до рендеру, помилка, повторна спроба,
  незалежні форми, багатокрокова операція й одноразові побічні ефекти.
- `OnlineShopCitiesPage.test.tsx`: реальна форма створення міста, подвійний клік
  і десять повторних submit під час незавершеного запиту.
- Регресійні тести змінених форм і перевірка TypeScript.

Це захист від повторних дій у поточному екземплярі інтерфейсу. Гарантія від
повторного виконання після перезавантаження, з іншої вкладки або після втрати
відповіді залежить від серверної ідемпотентності та існуючих механізмів
відновлення конкретної операції. Ця зміна їх не замінює.
