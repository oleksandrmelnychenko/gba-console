# Взаєморозрахунки за договором у Console

Кандидат додає набір 41 до спільної Console основи `5a9779094c40e78c3984e6ceb19c36f4af55be1f` (кошти 40 та явна база постачальника). Серверний контракт — `5c85ac8656f36d8b465dd278488b0831513ee3d5`. Це окремий точний договір, а не звіт за всіма контрагентами.

## Вибір та період

- Елементи вибору доступні лише за прийнятим серверним `settlementPeriod` версії 1 для набору 41. Обидві бази (`Fenix`, `Amg`) і типи (`ClientAgreement`, `SupplyOrganizationAgreement`) обираються явно. Тип договору контрагента не означає автоматично покупця.
- Довідник `GET /report/datasets/41/agreements` отримує точні `sourceWorld`, `nativeFamily`, `afterId` і `limit=30`. Розгорнутий API `Body` — масив. Сторінка повинна мати відповідну базу/тип, строге зростання ID, чинну ідентичність та відому валюту. Порожній або неповний підпис не підміняє ідентичність.
- `AgreementId` залишається десятковим рядком Int64, разом з `AgreementNetUid`. Зміна бази чи типу очищає обидва поля; старий асинхронний запит скасовується. Новий NetUID не замінює збережений автоматично.
- Період включає обидві дати, максимум 31 завершений день Києва, 1900–7998 роки. Початково обирається вчорашній день Києва. Остаточне покриття в межах одного покоління закриття перевіряє сервер.

Запит містить `settlementPeriod: {Version:1,SourceWorld,NativeFamily,AgreementId,AgreementNetUid,CurrencyBasis:'SettlementCurrency'}`. Рядки `[4,41,76,77]`: організація → валюта → контрагент → договір. Показники `[88,89,90,91]`: початок, надходження, витрати, кінець. Колонки та додаткові відбори порожні. FX, управлінська валюта, інші перетворення й дубльовані псевдоніми налаштування відхиляються до запиту.

Шаблон зберігає всі точні поля. Очищений вибір не відновлюється зі старого шаблону. Довідник не доводить наявність повного періоду: відсутній базовий залишок, змінена поточна прив'язка, непідтримувана валюта чи недоступна публікація повинні залишатись явною відмовою сервера. Поточний залишок не використовується як заміна.

Звичайні Preview/XLSX/PDF отримуються через серверний звіт; Console не розраховує суми. Перегляд вимагає атрибуцію `NativeSettlementPeriod`. Каталог міграції як повністю готовий не просувається; активація Source capture і live перевірки виконуються окремо Root.

## Локальна перевірка кандидата

Тести охоплюють контракт, межі днів/DST, обидві бази/типи, Int64, шаблони, очищення ідентичності, відмову FX, обмежені сторінки, скасування застарілих відповідей і форму. Точні результати TypeScript, ESLint, reports suite, Vite та ReactDoctor зберігаються в зовнішньому manifest кандидата. Не виконувалися браузер, live API, Source, SQL, Docker або .NET. Кандидат не опублікований.
