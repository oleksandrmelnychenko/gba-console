# Звіт коштів за період у Console

Окремий набір даних 40 показує початковий залишок, надходження, витрати й кінцевий залишок одного точного валютного запису рахунку. Він використовує нативний GBA звіт `NativeCashPeriod` і не перераховує суми у керівну валюту.

## Контракт

- Сервер оголошує `cashPeriod` версії 1 з фіксованими рядками `[43,40,42,41]` і показниками `[84,85,86,87]`. Без цього оголошення Console відхиляє набір даних.
- Рахунок обирається через `GET /report/datasets/40/currency-legs?afterId=0&limit=30`. `Body` містить масив точних ID у порядку зростання. Наступна сторінка використовує останній ID, без перетворення Int64 на JavaScript number.
- Запит передає тільки `cashPeriod: {Version:1,CurrencyRegisterId:string,CurrencyRegisterNetUid:string,CurrencyBasis:'AccountCurrency'}`. Назви рахунку, валюти й організації є підписами вибору, а не ідентичністю.
- Дати включні, до 31 дня, від 1900 до 7998 року, і закінчуються до поточного дня Києва. За замовчуванням обидві дати — попередній завершений день. Сервер остаточно перевіряє повне покоління підсумків дня закриття.
- Додаткові відбори, сортування, FX, приховані нулі й інші налаштування відхиляються до запиту. Збережений шаблон зберігає точні ID/NetUID; очищений рахунок не відновлюється зі старого шаблону.

Вікно перегляду та файли отримуються зі звичайного серверного звіту. Console не обчислює суми. Недостатнє покриття або зміна прив'язки рахунку має дати відмову сервера, а не порожній результат.

## Перевірка

Локально: точкові тести запиту, шаблону, сторінок довідника і форми; повний набір `src/features/reports`; TypeScript і Vite build; ESLint змінених файлів; React Doctor. Live API, SQL та браузер цим набором змін не викликалися. Публікація можлива лише разом із перевіреним серверним набором 40.
