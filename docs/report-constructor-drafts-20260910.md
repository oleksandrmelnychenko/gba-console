# Чернетки конструктора звітів

Конструктор автоматично зберігає змінені налаштування локально в поточній вкладці,
окремо для облікового запису користувача. `/reports/constructor` і
`/reports/stocks` використовують одну чернетку. Для тривалого зберігання та роботи
з інших браузерів залишаються особисті серверні шаблони.

Після оновлення сторінки або повернення до конструктора можна явно відновити чи
відкинути чернетку. До цього вибору початкові налаштування не перезаписують
збережену копію. Відновлення не формує звіт і не змінює серверний шаблон.

Чернетка містить обраний договір, періоди, групування, повний стан показників,
відбори та розширені налаштування, назву і початкову версію відкритого шаблону.
Порожні дати й незавершені значення можна відновити та доповнити; готовність до
формування перевіряється окремо. Незастосовані зміни всередині відкритого редактора
окремого відбору не є частиною налаштувань основної форми.

Після скидання, зміни набору даних, застосування швидкого налаштування або відкриття
іншого шаблону кнопка «Повернути попередні налаштування» відновлює стан до останньої
такої заміни. Це один попередній стан, а не історія кожного введеного символу.
Відновлення прибирає старий результат: файл треба сформувати знову.

Якщо серверний шаблон змінився, відновлення зберігає початкову версію чернетки.
Оновлення застарілої версії залишається заблокованим. Якщо склад полів або формат
чернетки вже не підтримується, оригінал залишається у вкладці до явного відкидання;
поля не видаляються автоматично. За недоступного чи переповненого сховища можна
продовжувати редагування, але конструктор повідомляє про відсутність автозбереження.

У чернетку не входять результати, посилання на файли чи дані авторизації.
Відновлення доступне лише своєму користувачу з правом формування звітів після
завантаження поточних наборів даних. Нові SQL-запити, серверні API та зміни 1С для
цього етапу не потрібні.

Перевірки й локальна інтеграція зафіксовані в приватному протоколі
`/root/evidence/report-constructor-wave37-2026-09-10/integration/`.
Цей етап сам по собі не означає розгортання на робочому сервері.
