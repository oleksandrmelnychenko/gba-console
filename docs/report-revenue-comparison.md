# Порівняння записаної виручки за договорами

Набір 16 додає порівняння записаної виручки EUR у двох явних періодах за структурою Клієнт → точний ClientAgreement.ID. Обидва періоди включають крайні дні Europe/Kyiv, можуть перетинатися, збігатися, мати різну тривалість або зворотний хронологічний порядок. Консоль не підставляє попередній місяць і не вирівнює дати.

`RevenueComparison` обов’язково містить рівно Version=1, From, To, BaseResource=4 та RoundingPolicy=NativeRawGrossFinalAwayFromZero2. Дати 1900–9998 перевіряються до запиту; зайві поля, дублікати регістронезалежних назв та невідомі версії відхиляються. Інші набори не підтримують цей параметр. Набір не підтримує довільні осі, Ordering, TOP, Threshold, ABC, HideZero, XYZ, Comparison, OneC чи оцінювання за поточним договором.

Показники 35/36 — поточна/порівняльна записана виручка, 37 — зміна EUR, 38 — зміна %. Будь-який непорожній активний піднабір зберігає порядок користувача, включно із завантаженням шаблону. Весь початковий список має 1–4 елементи відомих типів; активні типи унікальні. Усі чотири показники показуються і експортуються з двома десятковими знаками: 50,00 у відсотковому стовпці означає 50%, а не 0,5.

Сервер обчислює похідні показники та підсумки з початкових неокруглених сум, з одним остаточним округленням. Наприклад, raw C=0,006 і P=0,004 дають показані C=0,01, P=0,00, зміну=0,00 та 50,00%. Консоль зберігає цей результат і не перераховує його з показаних C/P. Усі чотири колонки локально неадитивні; пошук прибирає непридатні старі підсумки, CSV зберігає лише відібрані рядки, діаграма використовує значення окремих договорів без SUM або AVG.

Суми періодів відомі незалежно. Невідома сума не стає нулем; зміна і відсоток потребують обох відомих сум. Невідомий клієнт або відсутня назва не означає невідому суму. Відомий raw P=0 дає 100%, включно з повністю порожнім обсягом 0/0. Це конвенція KPI, не підтвердження економічного зростання. Порожній файл має вісім пояснень, стан порожнього обсягу, вибрані колонки та один серверний grand 0/0/0/100 без вигаданого договору. Пошук і CSV зберігають цей стан.

Відбори 1/2/6/9 використовують точний позитивний Data.Id товару/артикулу, клієнта або ClientAgreement. Числовий Id у браузері має бути safe integer; більші int64 передаються десятковим рядком. Підтримується об’єкт Data або рівно один старий JSON-string шар об’єкта, з перевіркою дублікатів Id перед JSON.parse. Голі скаляри, вкладені JSON-string шари, дублікати псевдонімів і невалідні int64 відхиляються. Поле Value описове, але залишається typed Int32: новий UI відправляє 0, не великий Id. Вимкнені умови зберігають позиції для дерева І/АБО; сервер виключає їхні гілки. Максимум 64 умови і 2 000 різних ідентифікаторів.

Профіль файлу перевіряє точну назву/осі/ресурс, два періоди, UTC час читання, вісім власних пояснень, вибрані повні назви показників із комами, числовий діапазон ±9 999 999 999 999,99 та формат 2dp. Фізичні переноси пояснень об’єднуються лише для показу; вихідні метадані залишаються у CSV. Автоматичне перенесення збережених налаштувань 1С не ввімкнено.

Це обчислення за поточними записами GBA і записаними сумами EUR. Повну числову, валютну, календарну, правову або функціональну тотожність 1С не підтверджено; «СравнениеРаботыКлиентов» має інші формули.
