# Частки продажів новим і повторним покупцям

Набір 17 формує частки записаних продажів EUR за структурою Клієнт → точний договір. Поточний і порівняльний періоди задаються явно, включають крайні дні Europe/Kyiv і можуть перетинатися, збігатися, мати різну тривалість або зворотний хронологічний порядок. Дати 1900–9998 років перевіряються до запиту.

Покупець новий, якщо до початку відповідного періоду немає його проведених продажів у доступній історії GBA. Історія охоплює всі договори й товари покупця незалежно від відборів цього звіту. Використовуються записані суми продажів EUR; поточні ціни договору, ПДВ, валютна конвертація й знижки повторно не застосовуються. Точний ClientAgreement.ID залишається окремою віссю; однакові умови договору не об’єднують різних покупців чи договори.

`BuyerSalesShare` / `buyerSalesShare` містить рівно Version=1, From, To, BaseResource=4 та RoundingPolicy=NativeBuyerSalesShareRawGrossFinalAwayFromZero2. Зайві поля, дублікати регістронезалежних назв, невідомі версії, невалідні дати й непідтверджені можливості сервера відхиляються. Інші джерела не підтримують цей параметр. Довільні осі, Ordering, TOP, Threshold, ABC, HideZero, XYZ, Comparison, RevenueComparison, OneC та оцінювання за поточним договором не підтримуються.

| Показники | Зміст |
| --- | --- |
| 39 / 40 | Частка продажів новим покупцям за поточний / порівняльний період, % |
| 41 / 42 | Зміна частки нових покупців, в.п. / відносна зміна, % |
| 43 / 44 | Частка продажів повторним покупцям за поточний / порівняльний період, % |
| 45 / 46 | Зміна частки повторних покупців, в.п. / відносна зміна, % |

Будь-який непорожній піднабір із 1–8 показників зберігає порядок користувача. Вісім колонок показуються та експортуються з двома знаками: 50,00 означає 50%, а не 0,5. Значення можуть бути від’ємними або перевищувати 100% через знакові суми; консоль їх не обмежує.

Сервер визначає частки, відносні зміни та підсумки з початкових сум до остаточного округлення. Консоль не обчислює їх із показаних часток, не виводить повторну частку як 100 мінус нова і не додає/усереднює відсотки. Наприклад, початкові частки 1/300 та 1/400 дають показані 0,33% / 0,25%, зміну 0,08 в.п. і відносну зміну 33,33%; відображені числа не є основою повторного розрахунку. Діаграми використовують окремі рядки договорів. Пошук прибирає старі службові підсумки; CSV містить відібрані рядки без вигаданого локального підсумку.

Невідома сума робить обидві частки її періоду порожніми, зберігаючи інший період незалежно. Похідні зміни потребують обох відомих періодів. За відомого нульового знаменника обидві частки дорівнюють нулю, включно зі знаковим взаємопогашенням. Нульова попередня частка дає відносну зміну 100%, включно з 0/0; це правило показника. Повністю порожній звіт має лише серверний загальний підсумок 0/0/0/100/0/0/0/100 у вибраному порядку, без вигаданого покупця чи договору. Невідомий покупець зупиняє формування на сервері.

Точні відбори товару/артикулу, клієнта та договору використовують позитивний Int64 в Data.Id. Безпечні цілі числа та десяткові рядки зберігаються без втрати точності; дозволено рівно один старий JSON-string шар об’єкта. Дублікати Id та невалідні ідентифікатори відхиляються. Описове Value у новому UI дорівнює нулю, зберігаючи серверний Int32. Вимкнені умови залишаються на своїх позиціях для дерева І/АБО.

API збереження та застосування шаблонів перевіряє параметри до операції. Копії зберігають порядок показників, дати, точні ідентифікатори й ревізію; дублікати псевдонімів залишаються видимими до відхилення. Скидання і зміна джерела очищують параметри попереднього набору. Браузерні шаблони проходять ту саму перевірку можливостей сервера.

Файл перевіряється за назвою, двома періодами, часом читання UTC, осями, ресурсом, вибраними повними назвами показників, вісьмома поясненнями, числовим діапазоном та точністю 2dp. Позначення цього звіту не можуть непомітно стати звичайним адитивним CSV після зміни назви. Це перевірка формату й узгодженості метаданих, а не криптографічне підтвердження походження. Повні початкові пояснення зберігаються в CSV; переноси рядків об’єднуються лише для показу.

Тести охоплюють усі 255 піднаборів показників, API/шаблони, дві дати, точні великі ідентифікатори, порожні й невідомі значення, від’ємні частки, CSV, читання бінарного XLSX та три типи діаграм. Окремі 18 синтетичних контрольних сценаріїв отримано незалежним Python Fraction-обчисленням із збереженими хешами входу та очікуваних результатів. Ці синтетичні дані не містять клієнтської інформації.

Це часткова реалізація за поточними записами й прив’язками GBA. Відмінності джерельної CostTurnover, історії, включення початкової межі, валюти/ПДВ і прав 1С залишаються непідтвердженими. Автоматичний імпорт налаштувань конструктора 1С та повна функціональна/числова відповідність цим звітом не заявляються. Жодних операцій запису в 1С консольна реалізація не додає.
