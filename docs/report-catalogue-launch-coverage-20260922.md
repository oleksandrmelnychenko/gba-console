# Запуск перенесених звітів із каталогу Консолі

Оновлення 25.09.2026: ізольований кандидат Консолі
`6510270e699586dffcaf9282fc4d34ed16cb5159` звірено з ізольованим
кандидатом `data-analytics`. Каталог має **105/105** `native_partial`
реалізацій із точними launch choices, 124 комбінації, 106 готових
конфігурацій і 22 різні готові запити. Цей перерахунок пройшов
`tests/report-catalogue-launch.integration.test.ts` із фактичними DTO
кандидата. Нижче наведено історичні числа аудиту 22–23.09; масовий запуск
усіх 22 SQL запитів у цьому кроці не виконувався.

Станом на 22.09.2026 серверний каталог містить 103 джерельні реалізації зі
статусом `native_partial`. У Консолі зареєстровано точні відповідності для всіх
103: звіряються ID звіту, ID джерела, база, `NativeDataSources`, поточні
можливості набору і право формування. Це обмежені нативні зрізи; повна
відповідність усім варіантам звітів 1С не заявляється.

Повторна звірка 23.09.2026 використала фактичний `Catalogue.json` (SHA-256
`7b99f6c497c08a1c66f07ba66599245b1a75511f617d1b7b4802016b2c5311f0`)
і серіалізовані поточні серверні набори (SHA-256
`8040e30194ae974f1abacca07949c944bb90dd840015c0020fb2289be88754a9`).
Усі **103/103** `native_partial` реалізації мають точний варіант запуску.
Вони дають 121 комбінацію джерела й набору: 104 готові конфігурації проходять
і перевірку Консолі, і серверну валідацію запиту. Інші 17 навмисно вимагають
явної дати стану, періоду порівняння, серії курсу або локального покриття Fenix
разом із глобальним типом ціни до формування.
Серед 104 готових конфігурацій є 20 різних SQL-запитів. Кожен із 20 виконано
на dev SQL Server через відповідний GBA-репозиторій; для ABC застосовано
окремий серверний крок класифікації. Це перевірка локального виконання,
не відповідність результатам 1С чи гарантія для кожної інсталяції SQL Server.
Додатковий SQL-прогін для ручних параметрів (порівняння періодів, XYZ,
курси, імпортовані платежі та ціни угод) пройшов **136/136** інтеграційних
тестів на dev SQL Server 23.09.2026.

Повторюваний gate:

1. У серверному репозиторії збережіть поточний DTO наборів у приватну тимчасову
   директорію через тест `CapabilitiesAndEveryNonemptySubsetAreExactAndInertForExistingSources`
   з `REPORT_IMPORTED_PAYMENT_FIXTURE_DIR`.
2. У Консолі задайте `REPORT_CATALOGUE_AUDIT_CATALOGUE` (шлях до серверного
   `Catalogue.json`), `REPORT_CATALOGUE_AUDIT_DATASETS` (цей DTO) та
   `REPORT_CATALOGUE_AUDIT_REQUESTS` (тимчасовий файл запитів), а тоді запустіть
   `tests/report-catalogue-launch.integration.test.ts`.
3. У серверному репозиторії задайте той самий `REPORT_CATALOGUE_AUDIT_REQUESTS`
   і dev `SALES_MUTATION_INTEGRATION_CONNECTION_STRING`, тоді запустіть
   `ReadyConsoleConfigurationsValidateAndExecuteOnDevSql`. Тест читає GBA SQL
   і не підключається до 1С.

Усі 103 реалізації можуть мати кнопку запуску, коли сервер повертає необхідні
можливості. Для двох реалізацій `ОтчетПоВозвратам` потрібна окрема можливість
`returnsOnly` набору 2. Вона відкриває записані повернення як додатну кількість
за клієнтом, товаром і днем. Причина, коментар, сума одиничних цін і відповідність
проведенню 1С не підтверджені; це частковий нативний зріз. Сервер позначає
показник «Кількість повернень» у табличному перегляді та Excel і ставить
заголовок аркуша «Звіт записаних повернень».

Набори 23, 24, 25 і 28 мають у Консолі окремі параметри Fenix/AMG, дату стану
або період згідно із серверним контрактом. Довідники відборів передають
обрану базу й зберігають точні строкові ID. Набір 26 відкривається з фіксованим
ABC-класом і товаром; частки A/B/C та показник редагуються за підтвердженими
можливостями сервера. Fenix `builtin:ВаловаяПрибыль` відкриває окрему наявну
панель консолідованого обороту 1С, оскільки набір 1 не є загальним набором
конструктора. AMG-реалізацію цього звіту не прив'язано до Fenix-панелі.

Точна Fenix-позиція для набору 27 — `builtin:ПродажиСравнениеПоТипуЦен` з
ID `5543ce7d-61fa-45e2-8b85-5cd40abaccb6`. Порожня СКД
`custom:fenix:0xabe8005056c0000811e03e97ca0bd65d` не має цього запуску.
На dev `ConcordDb_V5` 23.09.2026 є публікація знімка глобальних цін Fenix
(5 294 666 записів `PriceRegisterFact` загалом), але
`OneCTurnoverScope`, `OneCTurnoverDay` і `OneCTurnoverFact` мають по **0**
записів. Тому набір 27 не може сформувати локальний звіт навіть після вибору
типу ціни: потрібен повний підтверджений імпорт днів продажів для обраного
Fenix scope через наявний `OneCTurnoverSyncService`. На dev-конекторі
`data-concord` підключення Fenix/AMG не налаштовані; імпорт потребує доступу
до вихідного SQL 1С лише для читання. Точкова перевірка доступу 23.09.2026
підтвердила вхід у Fenix через 1С, але наявний SQL-профіль відхилив
read-only preflight через заборонену серверну роль; бізнес-таблиці не читалися.
Деталі — у серверному `docs/report-source-targeted-access-20260923.md`.

Позиції зі статусом `captured` без executable server dataset залишаються
видимими в каталозі без кнопки. Для «Типы цен покупателей» та «Отношение
дебиторской задолженности к продажам» бракує підтвердженого серверного
джерельного розрахунку; їхні наявні обмеження описані в серверному аудиті.
